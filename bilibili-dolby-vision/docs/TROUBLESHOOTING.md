# 故障排查

## 没有「杜比视界」画质选项

先确认账号具有观看权限，且该分 P 实际提供杜比视界流。视频标题不能证明平台为它提供了对应画质。部分 P8.1 视频在 B 站仅显示 HDR，当前脚本不会凭空新增杜比视界流。

再检查 Edge 所用用户配置是否安装并启用了脚本、Windows / 解码器 / 显示设备是否可用，以及 Edge 启动参数是否生效。在 `edge://version` 的命令行中可查看参数。

## 有选项，首次播放不亮，刷新后才亮

先检查脚本管理器中的版本是否为 `6.0.0`。保存升级后，需要刷新已打开的视频页一次才能替换旧页面中的钩子。

问题再次发生时，**先保留失败现场，不要刷新**。打开 Edge 开发者工具控制台，执行：

```js
copy(window.__BILI_DV_P84_AUTO__.diagnostics())
```

这会把当前脚本版本、视频标识和最近的诊断记录复制到剪贴板。若 `copy` 不可用，可直接输出并手动复制：

```js
window.__BILI_DV_P84_AUTO__.diagnostics()
```

同时记录视频链接、是否从右侧推荐进入、所选画质、Edge 版本和具体表现。

## 推荐列表切换后才出现问题

v6 增加了推荐切换入口与路由处理。诊断中重点查看：

| 状态 | 含义 |
| --- | --- |
| `route-changed` | 发现站内视频或分 P 路由变化 |
| `navigation-precheck-wait` | 已拦截播放器切换，开始核实目标视频 |
| `navigation-precheck-ready` | 预检结束；`verified` 表示当时是否已有可用的 P8.4 识别结果 |
| `p84-preverified` | 初始化段已确认符合 P8.4 |
| `p84-created` | 已在创建缓冲区时使用杜比声明 |
| `p84-metadata-confirmed` | 实际追加的初始化段与 P8.4 条件相符 |

若视频已切换但记录仍只包含上一条视频，请导出诊断；B 站切换接口变化可能需要重新适配。

## 预检失败或自动恢复失败

`probe-unavailable` / `startup-precheck-unavailable` 表示网络、跨域请求或超时等原因阻止预检。脚本会尽量从实际追加的数据学习，再尝试恢复播放器。

`player-rebuild-unavailable` / `player-interface-unavailable` 表示恢复接口不可用或失败。为避免循环重载，脚本不会无限重试。

`cache-mismatch` 表示实际初始化段与缓存不符。对应记录会被清除，当前缓冲区会拒绝继续以错误杜比声明追加数据；可切换普通画质恢复播放，再提供诊断。

## `only the HEVC HLG base layer`

这条提示表明所观察的解码信息仍指向 HLG 兼容基础层。应结合本脚本的 `p84-created`、`p84-metadata-confirmed` 和 `edge://media-internals` 检查当前播放，而不要仅依据画质菜单或一个标志判断完整解码过程。

## 过了一天或换了窗口后又需识别

脚本没有 24 小时过期计时器。缓存最多保留 512 条；清理网站数据、换 Edge 用户配置、使用新的 InPrivate 会话、视频流变化或较旧记录被移除，都可能触发自动重新识别。

## 临时停用

在脚本管理器中禁用该脚本并刷新视频页。也可在当前页面临时恢复已挂钩的接口：

```js
window.__BILI_DV_P84_AUTO__.restore()
```

再次启用时在脚本管理器中开启并刷新页面。脚本没有修改系统设置，也不会改写已下载的视频文件。
